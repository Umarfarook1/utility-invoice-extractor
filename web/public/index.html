Confidence is computed, never self-reported: it starts at 1.0 and drops when a quote is not in the document, when re-parsing the quote disagrees with the value, or when a validation rule fails.

One LLM call per document, wrapped in checks that do not trust it

The model does the part only a model can do: reading arbitrary layouts in any language. Everything that can be checked deterministically is checked by plain code.

  1. Ingest

    PDF text layer, page by page. Layout mode keeps labels next to their values.

    ingest.py

  2. Detect language

    Local detector as a free second opinion; the model reports its own.

    language.py

  3. Extract

    Strict JSON schema. Each field returns value, verbatim quote and page. A model ladder takes over on quota or overload.

    llm.py · prompts.py

  4. Ground

    Is the quote really in the document? If not, the value is treated as invented.

    verify.py

  5. Re-parse & validate

    Locale-aware parsing of the quote must agree with the value. Business rules on periods, units, meter reads.

    normalize.py · verify.py

  6. Score & export

    Field confidence, review flag, CSV plus a JSONL audit trail.

    pipeline.py · cli.py

Quote, then verify

Asking for the verbatim source text turns hallucination from invisible into detectable: a value whose quote is not in the document loses 60% of its confidence.

Extract in the original language

No translate-first step. Translation adds cost and corrupts exactly the tokens that matter: dates, decimal separators, units, names.

Null beats a guess

Missing fields come back empty and go to review. A plausible invented value silently corrupts an emissions inventory; an empty one gets fixed.

Cache by content

Answers are keyed by model, prompt, schema and document text. Re-runs are free, and the repo replays the full run offline without an API key.

    The one failure the checks cannot see

    Invoice 08 is a single PDF that holds two bills. The visible page is an Enel Ceará bill issued on 9 August 2018. Hidden under white boxes, the text layer also carries an older Enel Goiás bill issued on 7 July 2018. The model read the text layer, so it returned the hidden bill's dates. Every quote it gave really is in that text layer, which is why grounding passed and the row was not flagged.

    Text-layer checks cannot catch a text layer that disagrees with the rendered page. The fix is a render check: rasterize the page, OCR the regions the quotes came from, and flag any value whose quote is not visible. That is the first thing I would add before running this on customer documents.

    What I chose not to build, and what comes next

    Trade-offs made

    • One call per document, no chunking. Bills fit easily in context; chunking would split labels from values.
    • Text layer only, no vision. The brief rules out OCR. A vision pass is the obvious fallback for scanned bills.
    • Two providers behind one interface. Gemini (with a fallback ladder) and OpenAI; adding Claude is one class with an extract() method.
    • Gas m³ left unconverted. Converting volume to kWh needs each bill's calorific value; a default factor would be a silent guess.

    With more time

    • A larger labelled set per vendor template, with accuracy tracked in CI on every prompt change.
    • Second-opinion extraction from a different model on low-confidence rows only, so cost scales with doubt.
    • History checks: flag usage that jumps against the same meter's previous bills.
    • Emission factors joined on country and period to turn activity data into tCO₂e.
